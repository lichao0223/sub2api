# 数据分析开发方案与实现说明

更新：2026-11-06。代码已接入前后端；按用户要求停止本地测试，新增功能及迁移尚未完成运行验收。本文件描述实际实现，不将性能预算写成已验证结果。

## 功能与入口

管理员独立菜单「数据分析」，地址 `/admin/data-analytics`。复用 Vue、Go、PostgreSQL、TimingWheel、Chart.js 和 xlsx，不新增分析数据库或依赖。

- 组织和人员 SQL 同时上传，预检后应用；保留稳定 ID 和目录版本，支持人工确认重名。
- 组织展示第一级至第三级，完整路径留在历史归属中；深层组织的使用量与成本向上汇总。公司总数从人员事实计算，不把上下级表行相加。
- 年、单月、任意不连续多月；时间选择统一控制卡片、部门、人员、个人模型、趋势及导出。年/多月按月，单月按天，没有单独的趋势粒度开关。
- 个人明细包含模型、输入、输出、缓存写入、缓存读取、采购来源、按量成本六个分项、固定分摊及总成本。明确不计成本的模型仍计全部用量；缺价格的记录标为待核算。
- 所有 Token 展示、图表提示和导出使用 B/M/K。零显示 0，非零不足 1K 显示「＜1K」。接口整数和金额保留十进制字符串，前端不使用浮点累计金额。
- Excel 固定八表：总览、部门使用、个人使用、个人模型明细、成本组成、固定成本分摊、Token趋势、统计口径。姓名搜索只筛个人列表，导出取所选组织与月份全量。
- 系统设置的后台任务开关可运行时暂停、恢复，暂停后仍可读取已发布数据；依赖统计任务的导出准备、目录应用、人工匹配、补算均受开关控制。

## 目录与身份

输入格式为 `devp_org`、`devp_user` 两表的 UTF-8 字面值 SQL，每份最多20MiB、每表最多100000行、组织最多16层。只解析目标表 CREATE、INSERT 及有限的导出元语句，绝不执行上传 SQL。拒绝表达式、其他表、重复ID、循环、缺父节点、空姓名等；组织层级按父关系重建，不信任来源 level/path。

只持久化组织ID/名称/父节点/路径、人员ID/姓名/组织/状态，不保存密码、电话、邮箱。精简后的目录也限制20MiB。真实目录与原始 SQL 不提交仓库。

匹配优先级：人工确认/既有稳定ID、外部平台映射、双方均唯一的规范姓名。规范姓名处理全半角、空白和零宽字符；任一侧重名或稳定归属冲突都不猜测。平台用户使用现有 `user_usage_migrations` 的规范身份。

目录和人工匹配通过同一事务互斥锁、目录修订版本控制；冲突返回409。预检ID绑定当前管理员，24小时失效。相同目录重复应用不复制目录快照，并同步新增平台用户。后台每5分钟补充新平台用户的唯一匹配。

首次目录按当前组织回溯可用历史，后续目录按生效时间切换；历史组织路径随归属版本保存。人工确认未匹配人员时，仅回填仍具完整源数据的窗口；已有归属的人员改绑从确认时开始。超过源完整范围的任意日期归属修正拒绝，保留原统计。

## 采购成本口径

按量成本复用现有账号配置、成本方案历史价格、时间倍率，计算输入/输出/缓存写入/缓存读取/图片/按次六项人民币成本，不使用销售扣费金额。每个事实先按12位小数核算，再汇总，使分批归档不会引入不同的舍入结果。

固定采购以 `subscription_unit_id` 为单位：同一订阅多个账号只计一份采购，多个独立订阅分别计提。年付和月中起止沿用 `fixedDailyCost` 的有效区间和账期逻辑。

1. 计算该实例本月截至当前日期的已发生成本，当前月明确为暂估。
2. 对当月有有效使用的规范用户去重均摊。未使用者不参与；纯零用量占位不参与；有按次或图片等有效使用依据的记录可参与。
3. 无参与人时整笔计公共固定成本，不强塞给某个部门。
4. 个人份额再按其实际模型/历史组织的 Token 权重拆分，Token 全零时按有效请求数拆分。
5. 金额使用 NUMERIC(20,12) 与 decimal，按稳定顺序分配最后一位尾差。
6. 月内新参与人加入后重新发布整月分摊；参与人数及实例总额、个人份额可在个人明细核对。

```text
公司已核算成本 = 按量采购成本 + 固定订阅计提
               = 人员/部门成本 + 待归属人员成本 + 无人使用的公共固定成本
订阅计提 = 所有个人份额之和 + 公共固定成本
```

既有个人成本接口优先采用已发布月参与人与份额比例，将所选日期已计提金额精确分给同一批用户；未发布期间才沿用旧日分摊，避免两套已发布的个人参与规则并存。既有成本管理的固定计提取消“本月必须有请求”的条件；日分配也改为当月规范参与人均摊。数据分析个人金额使用自身完整月发布结果，避免从剩余原始请求推算历史参与人。已清理源数据的旧成本日表不自动伪造回填。

| `analytics_dirty_days` | 待处理日期、变更版本/原因/起点、失败次数与原因 |
| `analytics_bucket_state` | 完成时间、请求数、待核算数、已归档数/截止点、日明细到期标记 |
| `analytics_daily` | 日/规范用户/归属/模型/成本方式/来源/异常，完整 Token 和六项成本，13个自然月 |
| `analytics_archived_daily` | 已清理请求的同粒度基线，13个自然月，不复制请求明细 |
| `analytics_monthly` | 同维度月汇总与固定个人成本，60个自然月 |
| `analytics_org_daily`、`analytics_org_daily_versions` | 一级至三级及待归属池的日 Token；保留60月，版本表与月发布固定 |
| `analytics_publications` | 每月保留当前、上一个完整提交版本 |
| `analytics_fixed_totals`、`analytics_fixed_allocations` | 月实例总额/公共池与个人唯一份额，随月版本保留 |
| `analytics_rebuild_audit` | 补算请求及操作人，60个月 |
| `analytics_task_workers` | 实例心跳，回收7天前失联记录并保留最近成功记录 |

首版汇总使用普通表、业务唯一键和日期/人员/来源索引，配合有界删除。没有增加月分区轮转组件。现有 `usage_logs` 普通表、分区表都接入保护；若实测汇总表规模需要分区，再通过独立迁移处理。

常规分析只读已发布月模型统计和部门日趋势，不扫描原始日志。读请求使用只读一致快照；个人明细和导出携带每个所选月份的发布版本（未发布月份为0）。超过保留的两个版本时返回409要求刷新，不能混入新版本数据。

## 定时统计、压力与暂停

- 首次必须应用组织/人员目录后才启动归集和清理保护；不在空目录上提前发布历史。每5分钟运行，单实例只有一个归集循环；数据库事务 advisory lock 保证多实例不同时发布/改目录。
- 单轮最多31个按日批次，总预算4分钟，单批30秒；先处理当前月，再补旧日。
- INSERT/UPDATE 的语句级 transition trigger 按受影响日写脏标记，覆盖迟提交小ID、补录、跨日更新；不依赖最大ID游标。
- 工作读取脏版本后计算该日，整体替换日结果、重算月汇总及份额、复制部门日趋势，在一个事务内发布。
- 新写入或配置修改会增加脏版本；只有原版本仍相同才移除脏标记，避免计算期间写入丢失。
- 配置/价格变更与归档互斥，拒绝会改写已归档事实的追溯生效时间；按实际生效区间标脏；结束一个今天的旧价格版本不会重算过去几个月。归并身份可由保留月事实重算参与人与分摊，不要求仍有原始请求。
- 单日/月模型组合最多100000行，超限事务回滚、记录原因；不会截断后冒充完整数据。固定份额使用批量插入和每订阅一次的模型拆分语句，避免逐用户往返数据库。
- 失败日期退避1小时，不阻塞其他未处理日期；新变更可重试。页面显示覆盖天数、积压、失败示例、待核算数、更新时间和源历史缺口。
- 暂停后恢复会补齐期间遗漏日期，包括没有请求但应发生固定成本的日期。

任务开关由迁移921提供持久控制版本。全新部署默认关闭；兼容升级若已有成功成本统计则保留开启，不覆盖既有设置。控制刷新5秒，失联工作超15秒显示未知。启动登记与提交前校验通过短暂设置行锁协调；暂停取消运行 context，未提交事务回滚，已提交批次保留。控制读取/心跳失败时拒绝新工作。

开关同时控制原有成本增量和历史重算。每小时的分析保留期清理也进入任务控制；预检到期回收不依赖开关。

## 清理和数据量

原始请求仍沿用现有保留设置（建议90天），不擅自更改其他业务保留期。新分析日明细13个月，月明细与部门日趋势60个月；到期后不能查询该范围。

1. 首次启用先用短事务提交清理保护，再启动首个较重的日计算。
2. 父表 DELETE 的语句级触发器检查受影响保留日期：必须有核算状态、无脏任务、无待核算价格。未就绪拒绝整个删除事务。
3. 保留期删除把已删除子集通过同一解析函数折入日基线，累计归档数与截止点；后续重算使用“基线 + 仍在的请求”，不因原始日志减少而缩减历史。
4. 自动清理和人工清理通过父表分批删除，均触发保护。启用后不直接 DROP 非空日志分区：锁定后只删除空分区，非空分区走既有有界父表删除。
5. 显式单条纠错删除带事务内标记，不折入保留基线，重新标脏；日明细已到期时拒绝无法准确维护的纠错。启用后禁止 TRUNCATE 父请求表。
6. 超过日明细窗口的原始请求必须整月核算完成后才清理，并立即冻结该月由日数据重发的能力；日明细到期也先标记整月不可由残余日数据重新发布，再分批删除。超期迟到数据、缺源的改价/改组织保持原报表并标明错误；不把未知部分算成已确认零元。
7. 每小时每张明细/汇总表最多清理5000行；预检/审计/归属快照每批1000行，整轮30秒。清理与发布共用互斥，且只在提交时检查控制版本。
8. 普通 DELETE 依赖数据库 autovacuum 回收可复用空间，不承诺立即缩小磁盘文件；不执行高峰全表 VACUUM FULL。

长期暂停或成本长期 pending 会阻止相应原始请求清理；这是防止丢失统计的保护，页面积压状态需要关注。任务恢复后按预算追平，不能无限暂停还保证原始库占用不增加。直接数据库运维删除/子表操作绕过应用，不承诺自动恢复。

## 读请求与导出限额

分析查询全局最多2个并发，导出准备全局最多1个；超出返回繁忙提示。查询预算20秒，单次模型事实/份额最多100000行，导出JSON最多20MiB。大范围需按部门或月份拆分。

导出复用同一报表接口及快照，不增加服务端异步文件任务、对象存储或永久临时文件。浏览器 Worker 生成 xlsx，60秒超时结束 Worker；所有字段写成字面字符串，防公式注入，金额不转浮点。已完成的数据准备不会因后续暂停而变成服务器上的常驻文件。

页面每30秒在可见且未打开明细/维护窗口时刷新，旧请求可取消；个人翻页最多100条，不发送全量模型到普通列表。未增加 Redis 报表缓存：先用预聚合、有界读和数据库并发保护，避免额外缓存失效链路。

## 实际 API

管理员权限由现有统一中间件校验：

| 方法与路径（`/api/v1/admin` 下） | 用途 |
|---|---|
| `GET /data-analytics/directory` | 当前目录、身份匹配、最近20次预检/应用 |
| `POST /data-analytics/directory/preview` | multipart `organizations`、`people` 两份SQL |
| `POST /data-analytics/directory/apply` | 预检ID、生效时间、预期目录修订版本 |
| `PUT /data-analytics/identities` | 平台用户、人员ID、预期目录修订版本 |
| `GET /data-analytics/report` | year、mode、months、org_id、search、page、page_size、sort、user_id、versions、export |
| `POST /data-analytics/rebuild` | start/end，已发生且源完整，最多31天 |
| `GET /data-analytics/task-status` | 后台任务状态 |
| `GET/PUT /settings/data-analytics` | 系统设置总开关、预期控制版本 |

## 部署与验收

新增迁移921、922，由既有迁移机制加载；Wire已接入服务、仓库与 handler。进入管理员数据分析菜单，预检两份SQL，在系统设置开启统计，应用目录；页面明确显示首轮核算覆盖范围。没有把真实目录写入仓库或自动导入任何数据库。

测试矩阵见 `DATA_ANALYTICS_TEST_CASES.md`，另有解析、分摊、任务控制、身份匹配、普通/分区日志保护、月固定模型拆分、精确格式化与八表导出的自动化用例。早期任务控制检查曾执行；本次后续新增和修改的用例仅编写，遵照用户“不要本地测试了”未运行测试、构建、类型检查、数据库迁移、浏览器或容器验证。

部署验收仍需验证迁移、SQL执行计划、暂停时提交竞争、清理前后对账及真实规模容量。性能预算是限流与超时配置，不代表已验证的吞吐或延迟。单日源记录极多导致30秒内无法完成时，该日保留旧结果并退避，需在有性能数据后调整日内分批策略；目前不声称能在任意数据规模下追平。
